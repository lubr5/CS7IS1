Run a mapping with `python rml/run_rml.py rml/mappings/parks.rml.ttl` (instances go to /output). Pipeline: sources/*.csv -> mappings/*.rml.ttl -> output/*.ttl. IRIs are built from OBJECTID, not names, as names repeat or change.

### parks.rml.ttl
- source - sources/dlr_mainparks.csv, row per park
- subject - /id/park/{OBJECTID}, class dlr:Park
- properties - park_name -> rdfs:label; irish_name -> rdfs:label with language tag @ga; previous_name -> skos:altLabel; address -> schema:address; type -> dlr:parkType.

### sports.rml.ttl
- source - three triples maps: sources/dlr_tennisclubs.csv, sources/dlr_skateparks.csv, sources/dlr_leisurecentres.csv, row per facility
- subject - /id/tennis/{OBJECTID}, /id/skatepark/{OBJECTID}, /id/leisurecentre/{OBJECTID}, all class dlr:SportsFacility
- properties - Name -> rdfs:label (leisure centres: full_name -> rdfs:label, name -> skos:altLabel); Address -> schema:address; Phone -> schema:telephone; Email -> schema:email (tennis clubs and leisure centres only); dlr:facilityType is a constant per file ("Tennis Club", "Skate Park", "Leisure Centre").

### infrastructure.rml.ttl
- source - two triples maps: sources/dlr_publictoilets.csv, sources/dlr_wifiaccess.csv, row per item
- subject - /id/publictoilet/{OBJECTID}, /id/wifiaccess/{OBJECTID}, both class dlr:Infrastructure
- properties - toilets: Name -> rdfs:label; Opening Hours -> schema:openingHours. wifi: Name -> rdfs:label; WiFi4EU_Voucher -> dlr:wifiVoucher; Indoor_Or_Outdoor -> dlr:indoorOrOutdoor.

### counters.rml.ttl
- source - sources/counters.csv, row per footfall counter (7). Made by extra_data_clean/make_counters.py: script selects counters in footfall data and converts Date_of_op to an ISO date.
- subject - /id/counter/{OBJECTID}, class dlr:FootfallCounter
- properties - SITES -> rdfs:label; Date_of_op -> dlr:dateOfOperation (xsd:date); Lat -> geo:lat (xsd:decimal); Long -> geo:long (xsd:decimal).

### observations.rml.ttl
- source - sources/observations.csv, row per counter per hour (3,720 total). Made with extra_data_clean/make_observations.py: the original footfall file has one column group per counter, the script reshapes it to one row per counter per hour and skips hours with no data.
- subject - /id/observation/{obs_id}, class dlr:FootfallObservation
- properties - timestamp -> dlr:observedAt (xsd:dateTime); total -> dlr:totalCount, in_count -> dlr:inCount, out_count -> dlr:outCount (xsd:integer); counter_id -> dlr:recordedBy (IRI /id/counter/{counter_id}).

### areas.rml.ttl
- source - sources/invented_areas.csv, row per area (12). Invented, the open data has no area hierarchy.
- subject - /id/area/{area_id}, class dlr:Area
- properties - name -> rdfs:label; parent_id -> dlr:locatedIn (IRI /id/area/{parent_id}), giving the sub-area hierarchy.

### amenity_areas.rml.ttl
- source - sources/invented_amenity_areas.csv, row per amenity (20). Invented assignment of each amenity to an area.
- subject - /id/{amenity_type}/{amenity_id}, the same IRIs as the park, sports and infrastructure mappings (no class here, the type comes from their mappings)
- properties - area_id -> dlr:locatedIn (IRI /id/area/{area_id}).

### nearestTo.rml.ttl
- source - two triples maps: sources/nearestTo.csv and sources/invertedNearestTo.csv, row per amenity/counter pair (each amenity's closest counter), generated by data/nearestToGenerator.py and data/invertedNearestToGenerator.py
- subject - /id/{amenity_type}/{amenity_id} (nearestTo.csv); /id/counter/{counter_id} (invertedNearestTo.csv)
- properties - counter_id -> dlr:nearestCounter (IRI /id/counter/{counter_id}); amenity -> dlr:isNearestCounterFor (IRI /id/{amenity_type}/{amenity_id}).

### nearTo.rml.ttl
- source - sources/nearTo.csv, row per amenity/counter pair within range (102), generated by data/nearToGenerator.py, used by two triples maps
- subject - /id/{amenity_type}/{amenity_id} (amenity to counter); /id/counter/{counter_id} (counter to amenity)
- properties - dlr:nearTo in both directions, as an IRI to the other node. dlr:nearTo is symmetric in the ontology, and both directions are written out explicitly.

### geometry.py (not RML)
- source - data/geojson/*.geojson (parks, tennis clubs, skate parks, leisure centres, public toilets, wifi)
- subject - the same /id/{type}/{OBJECTID} IRIs as above, plus /id/{type}/{OBJECTID}/geom for the geometry
- properties - geo:hasGeometry -> geometry node; geo:asWKT -> WKT text. Plain Python (shapely) writes rml/output/geometry.ttl, because RML cannot map GeoJSON geometries. Used by the infrastructure-inside-park query.
